# Permissions EXPECTED in the Pass Tech release APK.
#
# The "Promises" CI job (.github/workflows/promises.yml) compares the MERGED manifest of the release
# APK against this file, both ways: a permission that appears without being listed here fails the
# build, and so does one listed here that disappears.
#
# Why: the Flutter app once shipped ACCESS_NETWORK_STATE, declared nowhere in the repository. It came
# with Google ML Kit (QR code scanner) and its telemetry transport, and nobody saw it because nobody
# looked at the merged manifest. A dependency added on a Tuesday can no longer widen the permission
# set unless someone writes the line here and owns it.
#
# NEVER add a line here to "make the build pass". Every addition comes with its justification in
# section 10 of the FIVE app/src/main/assets/legal/PRIVACY.{en,fr,de,it,es}.md, which are the
# documents the app shows.

# GitHub update check, and the opt-in breach check (HIBP, k-anonymity). Both documented in section 6
# of the privacy policy. Pass Tech does NOT promise "no Internet permission", unlike Agenda Tech,
# Notes Tech, AI Tech and App Manager Tech.
android.permission.INTERNET

# Optional biometric unlock, through androidx.biometric's own manifest: USE_BIOMETRIC, and
# USE_FINGERPRINT for Android 8 (API < 28). Documented in section 10 of the privacy policy.
android.permission.USE_BIOMETRIC
android.permission.USE_FINGERPRINT
